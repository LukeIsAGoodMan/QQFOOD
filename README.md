# QQ Food 597 运营管理系统 · v0.3

依据 [docs/PRD_v3.2.md](docs/PRD_v3.2.md) 搭建的首版，覆盖 P0-A 平台基础，以及 P0-B 经营闭环中最关键的一段：库存、调拨、质量、生产和追溯。

- 后端：FastAPI、SQLAlchemy 2，开发期用 SQLite，表结构可直接换成 Postgres
- 前端：React 19、Vite、Tailwind

## 运行

```bash
# 一次性安装
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cd frontend && npm install && cd ..

# 方式一：单进程（先构建前端，由后端托管页面）
./run.sh                      # http://127.0.0.1:8597

# 方式二：开发模式（前端热更新）
cd backend && ../.venv/bin/uvicorn app.main:app --port 8597 --reload
cd frontend && npm run dev    # http://localhost:5173，/api 自动代理到 8597

# 后端验收测试
cd backend && ../.venv/bin/python -m pytest -q

# 手机端验收（需先启动系统；会写入演示数据，请在演示库上运行）
cd e2e && npm install && npm run mobile   # 截图输出到 e2e/screenshots/
```

首次启动会自动写入演示数据。演示账号的密码都是 `qq597demo`，现场角色另有共享设备 PIN `1234`。

|---|---|---|---|
| boss | 老板 | qa | 食品安全/质量 |
| ops | 运营主管 | hrfin | 人事/财务 |

## 采购到收货闭环（PRD PUR-01～06）

「采购」页面现在有两个专用模块：

**需求与报价对比**
- 需求按版本保存，例如「v1 余量 5%」「v2 余量 15%」，新版本不覆盖旧版本。
- 报价挂在具体版本上。对比时按到手总价算（货款 + 税 + 运费 + 安装费），并标出最低总价和最快交期。
- 选中一家报价，一键生成采购单。

**采购单与收货**
- **审批**：采购单按行记录；金额超过审批额度（默认 2,000 美元，老板可以改）要老板电子签名批准，批准后标记下单。
- **收货分两步**：
  1. 现场提交收货单（按行填实收、Lot、拒收）。这一步不改库存。
  2. 拍签收单后，由仓管签名入账，系统写入库存流水，重复点击不会重复入库。
- **差异处理**：拒收会自动生成差异任务；剩下没到的部分可以「按短收关闭」。
- **发票与付款**：系统对比订单金额、按已收货计算的应付金额和发票金额。上传付款证明只代表「已付款待核对」，要财务签名核对后才算完成。

**联动**
- 老板总览新增三个指标：待审批采购、到货逾期、收货待入账。
- 扫采购单号能直接打开对应采购单。
- ChatGPT 可以查采购单，也可以提出修改预计到货（需要人确认后才生效）。

**线上已有的数据库**：部署后首次启动时，系统会自动把「采购」页面换成新模块，并发布为一个新版本。原来的通用采购台账模块只是隐藏，没有删除，可以在页面编辑器里重新显示，或者回滚到旧版本。老板总览也会自动加上三个采购指标。

## 切配生产：备料、出成率、损耗

在「生产」页的「切配生产」模块里，有三个页签。

**1. 配方与规格**

每个成品要设：
- 用哪种原料、出成率多少，例如「鸡腿肉切鸡丁，出成率 95%」；
- 出货每箱多少，例如 50 lb。

每种原料要设：供应商一箱多少，例如鸡腿肉 40 lb/箱、梅头肉 65 lb/箱。

这些都是随时可改的参数，换供应商、换箱子时直接改；以前的采购单和生产记录保留当时的数字。

**2. 备料计划**

系统按还没发完的订单，自动算出：
- 每个成品还要做多少（已扣掉成品库存）；
- 需要多少原料、还缺多少；
- 按供应商箱规向上取整，建议买几箱，以及预计剩多少原料（会算作损耗）。

比如 300 lb 鸡丁：300 ÷ 95% ≈ 316 lb，按 40 lb/箱就是买 8 箱 = 320 lb；300 lb 咕咾肉按 65 lb/箱就是 5 箱 = 325 lb。

勾选要买的原料后，可以一键生成采购单草稿，再去采购页补上单价、提交。

**3. 生产完工登记**

1. 选这批用的原料批次。剩下的原料有两种处理：
   - 「不要，算生产损耗」——默认选项，整批原料都算用掉；
   - 「只扣用量，剩余留库存」。
2. 逐箱称重。系统按「订单数量 ÷ 出货箱规」先列好格子（例如 6 格），每格填实际重量；留空的格子不计入。
3. 系统实时显示投入、产出、损耗和实际出成率。实际损耗比预计多 5 个百分点以上时会标红。
4. 完工时自动生成成品批次和每箱标签，这些箱子可以直接用来给订单发货。
5. 有放行权限的人可以勾选「完工即放行」（电子签名）；不勾的话成品是「待放行」，放行之前不能发货。

**追溯**：每箱成品都能查到用的是哪批原料。

**ChatGPT**：可以用 `get_production_plan` 回答「这周要备多少料」。

## 大统华订单与发货（PRD ORD-01～03）

**录单**：收到 PO 后，把 PDF 或照片发给 ChatGPT，说「录进工作台」。ChatGPT 会一张 PO 调用一次 `propose_order`；一个 PDF 里有几张 PO（例如 General、Freezer），就分别提交几次。提交后会得到两个链接：
- `confirm_url`：在手机上确认订单；
- `upload_url`：上传 PO 原件，订单确认后原件会自动挂到订单上。

**确认页会自动检查：**
- **重复 PO。** 系统 PO 是 9 位数字单号，按单号判断；中央厨房手写单的单号（如 CH-CK）会重复使用，所以要再加上日期和送货点一起判断。
- **商品对照。** 按大统华 Item# 或品名对到我们的 SKU。第一次对不上的行，在确认页选一下 SKU，下次就会自动对上。
- **价格和库存。** 单价和上次不一样会提示；库存不够发也会提示。

**称重品**（切粒鸡丁、肉粒等，基本单位是「磅」）：在「称重打标签」里一箱一箱录入重量，输完一箱按回车接着录下一箱。生成后打印箱标签，标签上有二维码、品名、批次和重量。可以选「称重入库」（这批货还没记过库存），或者「只打标签」（货已经在库存里）。

**发货**：
- **按箱卖的货**：系统按「先到期先出」自动挑批次，被隔离或待放行的批次会被拦下；
- **称重的货**：勾选或扫码选箱，自动累加重量，按实重计价；
- **超订量**：默认拦截，因为大统华会拒收。确实要多发，需要填写原因。

发货后可以打印 Packing Slip，上面有 PO 号、Item#、实发数量和重量、批次和箱号。

**送达**：上传签收单或送货照片；没有的话，写明原因后也可以登记送达。拒收要按行填写原因，系统会自动生成差异任务。金额按实发数量减去拒收计算。

**提醒**：老板总览新增「今明两天要交」「已过交期」「库存不够发」三个指标。

**其他**：改交期可以直接跟 ChatGPT 说，它会提交一个待确认的修改；追溯批次时能查到这批货发给了哪张 PO。

## 用 ChatGPT 批量导入 SKU、期初库存、加拿大调入

工作台是唯一的账本。你的 ChatGPT 负责整理数据（邮件、它的记忆、你们一起做的库存表），通过 MCP 接口批量提交；提交后不会马上生效，要你在手机上打开它给的链接，勾选确认后才写进系统。

| ChatGPT 工具 | 作用 |
|---|---|
| `get_master_data` | 先读系统里已有的 SKU 和仓库，避免重复建 |
| `propose_skus` | 批量新增或修改 SKU：编码、名称、分类、基本单位、单位换算、条码、安全库存 |
| `propose_stock_counts` | 按 SKU × 仓库 × Lot 提交数量。填的是盘点结果本身，不是增减多少；实盘的进实物库存，估计的进「未核数」 |
| `propose_inbound` | 多伦多或温哥华发来的货，生成一张调入单，确认后记为在途 |

提交后系统逐行比对，标出「新增 / 修改 / 无变化 / 疑似重复 / 有错误」：
- 疑似重复的行默认不勾选；
- 有错误的行不能确认。

确认页在「资料中心 → 批量导入」。

**第一次导入真实数据的步骤**
1. 用 `boss` 或 `admin` 登录，在「用户与角色」页最下面点「清空演示数据」。系统会先在数据盘上自动备份一份数据库，再清空。
2. 跟 ChatGPT 说：「先读工作台主档，把我们的 SKU 表用 propose_skus 导进去」。然后在手机上打开它给的链接确认。
3. 再说：「把最新库存按仓库和批次用 propose_stock_counts 导进去」，同样打开链接确认。
4. 从此以后查库存以工作台为准，不要再单独维护另一份库存表。

## 团队模式（权限）

默认是 **精简模式**，适合现在两三个人的团队：

- **老板、主管、系统管理员**：拥有全部权限。可以本人核验、本人批准、本人入账，系统会标注「本人」并留下记录。
- **现场员工**：只做当班检查、提交收货、上报异常、拍照，看不到密码和财务附件。

以后人多了，在「用户与角色」里切换到 **标准模式**：按岗位分权（采购、仓管、质量、财务），核验、放行、入账等关键步骤要求换人复核。只有老板或系统管理员能切换。

## 多伦多、温哥华来的货：走调入，不走采购

这类货在加拿大已经买好了，运到 597 只是公司内部调货，所以在「库存与调拨 → 新建调拨 / 调入」里录：

- 「从哪里来」选 **多伦多（公司）** 或 **温哥华（公司）**。这两个地方标为「不管账」，系统不追踪那边的库存，发货时不会因为对方账面不够而卡住。
- Lot 按对方单据直接填写。
- 勾选「对方已经发出」，货就按单据数量记为「在途」。
- 货到后点「现场签收」。部分到货、短少、破损会自动生成差异任务。
- 装箱单、BOL、报关单可以作为附件挂在这张调入单上。

没有提前建单、货直接到了的，用「库存 → 收货」，在「货从哪来」里选「公司调入」即可。

还有别的来源地（比如以后的新仓库），在「库存 → 仓库与来源地」里添加。

## 部署到 Render

仓库已经带好 `Dockerfile` 和 `render.yaml`。在本机按 Render 的方式构建并运行过，以下几项都验证通过：
- 环境变量里设置的密码和 PIN 生效，默认演示密码失效；
- 容器重启后数据保留；
- AI 接口返回公网网址。

| 设置 | 值 |
|---|---|
| 服务类型 | Web Service，Runtime 选 Docker（Render 会自动识别仓库里的 Dockerfile） |
| 区域 | Oregon |
| 实例 | Starter 或更高。免费实例不能挂磁盘，闲置会休眠，重启会丢数据 |
| 磁盘 | Mount Path 填 `/var/data`，5 GB |
| Health Check Path | `/api/health` |
| 环境变量 | `QQ_DATA_DIR=/var/data`<br>`QQ_DEMO_PASSWORD=<自己设的强密码>`<br>`QQ_DEMO_PIN=<6 位数字>`<br>`QQ_PUBLIC_URL=https://<服务地址>`（第一次部署成功、拿到地址后再补上） |

安全相关的设置：
- 公网上不会显示演示账号提示；
- 同一账号连续 8 次登录失败，锁定 15 分钟；
- 数据库、上传文件和密钥都存在 `/var/data` 磁盘上。

想重置演示数据：在 Render 的 Shell 里运行 `rm /var/data/qqfood.db*`，然后重启服务。

## AI 助手接口（PRD §9.11 AGT）

系统不内置 AI 对话。它开放一层受控接口，老板和员工可以在自己手机上的 ChatGPT（或 Claude）里直接查询、提出修改。AI 以授权人本人的身份调用，权限、证据规则和版本冲突检查都和网页端一样。

- **接入方式**：两条路线共用同一套 19 个工具。
  - MCP 连接器：地址 `/mcp`，在 ChatGPT 开发者模式里添加。
  - 自定义 GPT + Actions（备用）：Schema 地址 `/agent/openapi.json`。
- **授权**：OAuth 2.1，支持 ChatGPT 自动注册客户端，带 PKCE。每人在「我的设置 → AI 助手」里自己开启并授权，可以单独撤销某个连接，关闭开关会撤销全部连接。
- **AI 能做什么**：
  - 读取：总览、搜索、任务、记录、库存、调拨、追溯、待核验证据、资料中心队列、联系人。
  - 低风险写入：写评论、上报异常、更新自己任务的进度（不能标记完成）。
  - 提出变更：只生成待确认变更，进入资料中心，由人确认后才生效。同时保存一份「AI 转述（非原件）」存证。
  - 原件上传：AI 生成一个 30 分钟有效的手机上传链接，只能传到指定的那一项，不用登录。
- **永不开放**：质量放行、证据核验、库存过账、付款、密码、人事附件、用户与权限、页面发布。
- **审计**：每次调用都记入审计日志；AI 改动过的地方，修改历史里标注 `agent:ChatGPT`。

**上线步骤：**

1. 部署到公网 HTTPS（建议美国西部区域），设置 `QQ_PUBLIC_URL=https://你的域名`。本机地址 ChatGPT 访问不到。
2. 老板登录系统，在「我的设置 → AI 助手」里开启。
3. 选一条路线：
   - **连接器**：在电脑上的 ChatGPT 打开 设置 → 应用与连接器 → 高级 → 开发者模式，创建连接器，填 `https://域名/mcp`，认证选 OAuth。
   - **自定义 GPT**：在 `backend` 目录运行 `../.venv/bin/python -m scripts.create_gpt_client "老板的 GPT"` 拿到 Client ID 和 Secret，再按「我的设置」页里的步骤配置 Actions。
4. 在手机 ChatGPT 里实际试一次（PRD 附录C 的 C-15）。连接器在手机上能用就用连接器，不能用就改用自定义 GPT。
5. ChatGPT 个人版用户建议在 设置 → 数据控制 中关闭「为所有人改进模型」。

**已验证的部分：**
- `backend/tests/test_agent.py` 的 9 个测试全部通过，覆盖发现与 401 提示、开启与角色限制、读取分级、提出变更需人工确认、低风险写入与版本冲突、不泄露密码和人事附件、撤销与刷新令牌轮换、上传链接、自定义 GPT 的机密客户端。
- 用官方 MCP Python SDK（2.3.0）对真实运行的服务走完 OAuth，初始化协议 2025-11-25，列出并调用了工具。
- 手机验收脚本模拟了「ChatGPT 授权 → 提出变更 → 未登录手机上传原件 → 在系统里确认」整条流程。

**还没验证的部分：** 真实的 ChatGPT 连接。要等系统部署到公网后，用老板的账号实测。

## 手机端适配（PRD §10.5 MOB）

老板可能只用手机验收，所以每个关键节点都按手机标准重新做过：

- **布局**：表格在手机上改成卡片，例如库存卡片先显示可用量；看板改成「状态切换 + 单列列表」，不用左右滑；页面不出现整页横向滚动。
- **触控与输入**：可点区域至少 44px，次要图标按钮至少 36px；输入框字号 16px，iPhone 上点输入框不会自动放大；数量字段弹出数字键盘。
- **老板入口**：老板登录后直接进入老板总览，指标卡两列并排，点击可下钻，「统计口径」可以展开查看。
- **导航与搜索**：底部固定四个入口（总览/当班、任务、资料、菜单）；手机上有全屏搜索。
- **弹窗与操作按钮**：弹窗从底部弹出，较宽的弹窗直接全屏；任务详情的操作按钮固定在屏幕底部；适配 iPhone 刘海和底部横条。
- **证据查看**：PDF 在手机上用系统查看器打开，可以翻页；图片可缩放、旋转。
- **页面编辑器**：手机上分成「模块 / 配置 / 预览」三个页签，支持触屏拖动排序，也保留上移/下移按钮。
- **主屏幕**：可以「添加到主屏幕」，打开后是独立窗口。

`e2e/mobile-check.mjs` 用本机 Chrome 模拟 iPhone 14 触屏，覆盖两部分：
- **逐页检查**：页面溢出、输入框字号、按钮大小。
- **关键流程**：老板看总览、下钻、搜索、看任务；员工 PIN 登录后拍照提交检查表；仓管收货、发运和部分签收；质量隔离和放行签名；主管核验并关闭整改、在资料中心确认变更、在手机上新建并发布页面。

目前 **95/95 全部通过**（含 AI 助手、采购、调入、批量导入、大统华订单、切配生产流程）。以下两项需要真机人工确认，脚本覆盖不了：
- 真实 iOS Safari 和安卓机上「添加到主屏幕」后的表现（T-MOB-09）。
- 真机打开 PDF 的效果。

## 尚未实现 / 与 PRD 的差距

以下都还没做：

- **识别**：资料中心还没接 OCR/AI 识别，现在由人对照原件手动提出变更。变更集、冲突处理和证据链已经按识别结果的接入方式设计好。
- **登录安全**：MFA、PWA 推送、邮件通知。
- **离线**：离线采集（目前只提示断网）。
- **打印**：热敏打印机直连。
- **扫码限制**：摄像头扫码依赖浏览器的 BarcodeDetector，安卓 Chrome 可用；iOS 只能手动输入，或用 USB/蓝牙扫码枪。
- **采购与订单**：目前是通用记录，还没有逐行核销、补货 PO 关联和付款核对。
- **生产**：没有生产准备检查和工序模板，配方/SOP 版本只是一个引用字段，没有版本库。
- **其他业务页**：招聘、员工、考勤、财务成本页都还没建（可以先用「台账」模板配出基础台账）。
- **字段迁移**：只拦截危险的字段改动，还没有迁移预览和迁移工具。
- **文件安全**：只校验文件类型，没有恶意内容扫描；HEIC 在非 Safari 浏览器无法预览，但原件保留。
- **外部接入**：Gmail、QuickBooks 属于 P2，未开始。
- **部署**：单机 SQLite，还没有备份和恢复演练。正式上线建议改用 Postgres 加对象存储，并配好 HTTPS 和定期备份。
