# QQ Food USA · 597 运营管理系统

产品需求文档 PRD v3.2｜2026-11-03｜供产品、设计、开发与业务负责人评审

**本版核心：** 保留完整的配置式页面编辑器；Notebook改为内部共享账号模式；补齐扫码与标签、正反向追溯、电子记录、现场多语言与共享设备、推送通知和登录安全；统一需求编号，增加业务结果指标，并把初始化清单、指标口径、待决策事项和手机线框移入附录。v3.1起，**手机端适配是全系统的验收前提**：老板可能只用手机验收，每个关键节点必须能在手机上看清并完成（§10.5）。v3.2起，**系统不内置 AI 对话**，而是开放受控的 Agent 接口，让老板和员工在手机上的 ChatGPT（或 Claude）里直接查询和提出变更（§9.11）。

## 1. 产品目标与范围

为597 Monterey Pass Rd建立统一运营工作台，使远程老板能查看生产准备、订单履约、库存风险、建设进展、经营费用和待决策事项；现场人员通过手机或共享平板完成任务、扫码录入数量并上传证据。

核心原则：一次录入，多处引用；计划、实际和核验分离；每项关键工作有负责人、时限和完成标准；没有数据显示未知；模块扩展不能破坏库存、权限或历史记录；现场流程以现场人员的语言和操作条件为准。

### 1.2 首版边界

首版支持单公司、597主场地及多个外库；数据结构预留多场地。首版提供受控的配置式页面编辑器（完整包含草稿、发布、回滚和字段迁移），不承诺任意代码或任意业务逻辑都可无代码实现。新增复杂算法、外部系统连接或新型业务动作仍需开发扩展。

首版不自行开发完整工资税申报、完整会计总账或自动对外采购付款；保留导入导出和后续对接能力。Notebook面向内部共享账号的日常查阅，不定位为企业级密码保险箱。本文交付PRD，不表示系统已经上线或邮箱已启用持续同步。

## 2. 用户、角色和访问范围

### 2.1 角色

| 角色 | 日常工作 | 默认权限 |
|---|---|---|
| 老板 | 查看全局、批准预算、处理重大异常 | 全业务汇总及授权范围内明细；敏感人事文件单独授权；可管理Notebook共享 |
| 运营主管 | 管理任务、供应商、建设项目、协调生产配送 | 编辑运营记录、分派任务、核验完成；可管理Notebook共享 |
| 采购人员 | 询价、下单、收货协调 | 采购与供应商；付款审批按额度授权 |
| 仓管 | 收货、盘点、调拨、拣货、打印库位/托盘标签 | 授权仓库与库存操作；不能绕过质量冻结 |
| 生产负责人 | 排产、领料、工序记录、完工、打印批次标签 | 生产批次与岗位任务；质量放行需相应权限 |
| 食品安全/质量负责人 | 卫生核验、批次放行、异常整改、追溯与模拟召回、标签模板批准 | 质量记录、SOP审批及受影响库存 |
| 人事/财务 | 招聘入职、考勤审核、账单与报销 | 各自敏感数据范围；跨域权限另行授予 |
| 现场员工 | 执行当班任务、打卡、扫码、上传照片 | 自己或岗位分配的记录和适用SOP |
| 页面管理员 | 配置页面、模块与导航 | 配置权限不自动授予人事、财务、Notebook密码等业务数据权限 |
| 系统管理员 | 用户与角色、共享设备登记、上传限制、保留策略、连接配置、系统参数 | 系统配置与审计查看；不自动获得业务敏感数据和Notebook密码；不能修改或删除审计日志 |

### 2.2 核验权限

“核验人”不是独立角色，而是按记录类型授予的权限：例如收货核验授予仓管主管，清洁核验和批次放行授予质量负责人，付款核对授予财务。核验权限在规则中配置，可授予角色或指定人员。

SEC-06：操作者能否核验自己提交的记录由规则明确；批次放行、库存调整、敏感更正默认必须由他人核验。

首版供应商、司机、外库联系人作为联系人管理，不默认开放外部账号。未来外部访问必须限制到明确单据和附件。

### 2.3 登录、会话与账号安全

SEC-01 登录方式：个人设备用邮箱或手机号＋密码登录；登记过的现场共享设备上用个人PIN快速切换（见FLD-02）。预留Google Workspace SSO。

SEC-02 MFA：老板、人事/财务、系统管理员账号必须启用MFA（首选认证器App验证码，备选邮箱验证码；短信可选，待技术评审）；其他角色可选，由系统管理员按角色开启。

SEC-03 会话：个人设备闲置12小时需重新登录，最长会话30天；共享设备闲置2分钟锁回人员选择屏。用户可查看自己的登录设备并远程登出；系统管理员可强制登出某人全部会话。权限撤销或停用账号后，新请求立即失效。

SEC-04 密码与PIN策略：密码至少10位，拒绝常见弱密码；连续5次失败锁定15分钟；重置走一次性限时链接。PIN 4–6位，只在已登记共享设备有效，不能用于个人设备登录；连续5次失败锁定该PIN并通知主管。

SEC-05 权限在服务端执行，前端隐藏按钮只改善体验。登录、失败、MFA变更、权限和角色变更、强制登出均记入审计。

## 3. 模块化产品架构

### 3.1 四层结构

| 层级 | 含义 | 示例 |
|---|---|---|
| 工作空间 | 公司、场地、角色入口和导航 | QQ Food USA / 597 |
| 页面 | 某一主题的工作入口，可新增和分组 | 库存、生产、车辆、未来的冷库巡检 |
| 页面模块 | 可复用的展示或操作组件 | 指标卡、表格、看板、检查表、证据区、时间线 |
| 业务记录 | 被页面引用的真实业务对象 | 一张采购单、一个批次、一次清洁检查、一位候选人 |

页面是业务数据的视图；移动或删除视图不删除业务数据。同一批次可同时出现在生产页、质量页、老板首页，不产生三份独立记录。

### 3.2 页面管理要求

MOD-01：管理员可从模板或空白创建页面，设置名称、图标、导航分组、场地、说明、默认负责人、可见角色和固定链接。支持复制、重排、停用、归档以及恢复。

MOD-02：编辑流程为创建草稿 → 添加模块 → 配置字段与数据来源 → 手机/桌面预览 → 权限检查 → 发布版本。草稿不影响线上页面；可回滚到历史布局。改名不改变记录ID或已有深链接。

MOD-03：复制页面默认只复制布局、字段配置和规则，不复制业务数据、附件、人员隐私信息或Notebook密码；管理员需明确选择继续引用原数据源，或创建新的通用记录集合。

### 3.3 页面内模块管理

MOD-04：每个模块都有稳定ID、类型、版本、标题、数据来源、过滤条件、可见范围、操作权限和布局配置。可添加、拖动、调整宽度、折叠、复制和隐藏；同时提供按钮排序，保证手机和键盘可操作。

MOD-05：模块移除前显示影响：仅移除展示，还是归档模块自身的通用记录；首版默认只移除展示。有关联证据、规则或引用时必须提示，不做隐式级联删除。

MOD-06：模块配置发布失败时保留草稿；不支持的组件版本显示明确提示和只读占位，不使整页不可用。

### 3.4 首版组件目录

| 组件 | 能力 | 证据入口 |
|---|---|---|
| 指标卡 | 数值、目标、趋势、更新时间、下钻 | 查看来源记录及计算口径附件 |
| 数据表格 | 筛选、排序、列配置、分页、批量操作 | 行级附件图标和详情证据区 |
| 看板/任务列表 | 按状态分组、负责人、截止日 | 卡片直接拍照或上传 |
| 记录表单 | 结构化字段、校验、条件显示、扫码填值 | 表单级及字段级附件 |
| 检查表 | 每项结果、实测值、不适用理由 | 单个检查项关联证据 |
| 图片/PDF证据区 | 缩略图、预览、分类、核验 | 原生上传、已有文件引用 |
| 时间线/评论 | 事件、沟通、状态变更、提及人员 | 评论附件与业务证据可区分 |
| 日历 | 交货、检查、保养、面试、到期日 | 事件关联记录证据 |
| 文档/SOP | 当前有效版本、历史、阅读培训 | 原文与批准记录 |
| 图表 | 按受控字段聚合、趋势、下钻 | 原始记录及统计来源 |
| 关联记录 | 订单到调拨、采购到验收等 | 访问原记录证据，仍校验权限 |
| 异常/审批 | 阻碍、整改、核验和审批 | 必需证据清单与签核 |
| 扫码入口 | 调起摄像头扫码，定位记录或填入当前表单 | 扫码事件随记录保存 |
| 追溯查询 | 输入或扫码Lot，展示正反向链路 | 链路上每个节点的原始单据证据 |

每个模块都提供统一“证据”入口，但展示位置按组件不同优化；指标卡引用原始单据证据，避免把随意上传的照片当成数字依据。

### 3.5 可配置与需开发的边界

MOD-07 **管理员可配置：** 新页面、通用记录表、文本/数值/日期/金额/选择/人员/关联记录/附件/扫码字段、必填规则、视图、状态、以下规则类型及审批节点。

| 规则类型 | 触发 | 动作 | 示例 |
|---|---|---|---|
| 必填与条件显示 | 字段值、状态 | 显示/隐藏/必填 | 检查结果为“不合格”时必填整改说明 |
| 状态流转校验 | 状态变更 | 要求字段、证据、核验权限 | 设备验收需验收表＋安装后照片 |
| 到期提醒 | 日期字段临近或已过 | 通知负责人，超时升级 | 保险到期前30天 |
| 缺记录提醒 | 周期内未提交应填记录 | 通知、首页显示缺记录 | 每班冷库温度未填 |
| 阈值→生成整改任务/异常 | 数值字段超出设定范围 | 创建整改任务或异常，指派负责人，关联原记录 | 冷库温度超出阈值生成整改任务 |
| 状态变化通知 | 指定状态进入/离开 | 通知指定角色 | 批次被隔离时通知生产与订单负责人 |
| 审批节点 | 金额、数量或类型条件 | 进入审批，签名后继续 | 采购超过额度需老板批准 |
| 证据要求 | 状态变更 | 指定证据用途、数量、核验人 | 收货需签收单 |

阈值、频率等参数由相应业务负责人设定；监管相关参数（如温度、浓度）由食品安全负责人批准，页面管理员不能自行修改。

MOD-08 **需开发扩展：** 新型交互组件、库存过账行为、生产领退料逻辑、追溯算法、特殊计算模型、标签打印机驱动、QuickBooks/打卡机等连接器。

MOD-09：库存数量、批次放行、付款审批等核心字段不可通过页面编辑器任意改类型、删除或改写计算逻辑。公式仅使用允许的函数和字段，不能执行任意脚本。

MOD-10：字段新增默认可空；设为必填需给出旧记录处理办法。改名保留字段ID。字段停用保留历史值。破坏性变更需迁移预览、影响检查和回滚方案。

### 3.6 “10分钟建页面”基准

## 4. 全系统统一证据管理

### 4.1 上传与预览

EVD-01：所有业务详情、通用模块、检查项和任务提供“拍照 / 上传文件 / 选择已有证据”入口。电脑支持拖拽和粘贴图片；手机支持拍照及相册批量选择。

EVD-02：首版支持JPG、PNG、HEIC和PDF；HEIC生成兼容预览并保留原文件。DOCX、XLSX、CSV可作为附件下载，在线Office预览后续扩展。默认单文件上限50MB，每批20个，可由系统管理员调整；超限上传前提示。

EVD-03：图片可缩放、旋转查看；PDF可分页、缩放并打开指定页。标注和裁剪作为派生版本保存，不覆盖原件。预览失败保留原件下载入口和失败原因。

EVD-04：逐文件显示进度、成功与失败，可重试失败文件且不重复已成功项。上传未完成的文件不能满足完成状态的凭证要求。

### 4.2 证据对象与关联

EVD-05：一份文件可以关联采购、验收、报销等多个记录，无需重复上传。每次关联应保存“用途”，例如发票、签收单、安装前、安装后、整改证明、批次标签。

EVD-06：证据对象保存以下信息。

| 信息 | 要求 |
|---|---|
| 身份 | 文件ID、版本、原始名称、类型、大小、校验值 |
| 来源 | 上传人、上传时间、拍摄/发生时间、来源邮箱或导入来源 |
| 业务关联 | 记录ID、模块实例ID、可选字段/检查项ID、用途 |
| 核验 | 未核验/通过/驳回/已取代、核验人、时间、意见、电子签名 |
| 生命周期 | 有效日期、到期日、替代关系、保留策略和归档状态 |
| 可检索信息 | 标题、说明、标签、OCR文字及识别状态 |

上传时间与事件发生时间分开；相机EXIF只作为参考，不能证明实际发生时间。文件核验通过不自动代表整个业务事项完成。

### 4.3 权限、版本与删除

EVD-07：证据读取同时校验文件权限和访问上下文的业务权限；关联到更开放的页面不能放宽原文件权限。未授权用户不能通过预览URL、搜索、缩略图、导出或OCR结果获得文件内容。

EVD-08：同一证据对不同业务关联分别核验；某发票可在采购侧确认收到，但财务侧仍待核对。引用关键业务记录时固定文件版本，替换文件不静默修改已批准事项。

EVD-09：解除关联只移除该处引用，不删除原件。存在其他引用、保留要求或审批历史时禁止普通用户永久删除。归档、替换、下载、核验和删除动作记录审计日志。保留期限按REC-03配置。

EVD-10：文件上传后进行类型和恶意内容检查；附件使用受控访问的短时链接，不以永久公开链接存储。加密PDF可保存为待处理附件，不能标记为已成功预览或OCR。

### 4.4 证据规则

EVD-11：关键状态可以要求某类证据、结构化字段及指定核验权限。例：设备验收需要验收表与安装后照片；收货需要实际数量和签收依据；清洁检查按检查表要求记录结果，失败项必须整改及复查。

EVD-12：确需例外时只能由授权主管填写原因并批准，保留异常标签；质量隔离等不可豁免限制由专用业务规则执行。

EVD-13：首版提供手动上传后的OCR/AI识别、记录匹配及待确认更新建议（P0-B）；后续接入Gmail和QuickBooks（P2）。识别不直接修改库存、放行批次或提交付款。原文件、页码或图片区域与提取结果同时可查看；详见第9节。

### 4.5 任务状态与证据状态的对应

证据核验状态挂在每条证据关联上；任务和单据的显示状态由“是否报告完成＋必需证据是否齐全＋是否核验”共同决定。

| 显示状态 | 条件 | 计入完成 |
|---|---|---|
| 进行中 | 尚未报告完成 | 否 |
| 待核验 · 缺证据（标签） | 现场已报告完成，但必需证据或结构化字段未齐，或文件上传未完成 | 否 |
| 待核验 | 已报告完成，必需证据和字段齐全，等待有核验权限的人 | 否 |
| 已完成（已核验） | 核验通过并完成电子签名 | 是 |
| 已完成 · 例外 | 授权主管批准例外，有原因和异常标签 | 是，单独统计 |
| 退回 | 核验驳回，回到进行中并保留驳回意见与原证据 | 否 |

“有证据但待核验”与“已报告完成但缺凭证”都不能显示为已完成。不需要核验的普通任务，由规则配置为报告完成即为已完成。

## 6. 核心业务规则

### 6.1 库存与补货

INV-01：库存变动采用事务流水：收货、出库、调拨发出、调拨签收、领料、退料、生产入库、报废、盘点调整均保留来源单据、操作人、扫码或手输标记。修正已过账记录通过冲销与更正，不覆盖历史流水。

INV-02：库存分为以下几类，分别展示：

- **实物账面库存**：已通过收货、盘点等授权流水核验入账的数量。
- **待核验库存**：已报到货但未点数、导入暂估、外库报告未核对、单位不明的数量。它不计入实物账面库存，不能被预留、分配或领用；核数确认后通过收货或盘点流水转入实物账面库存。
- **不可用库存**：实物账面库存中被隔离、冻结、过期或损坏的部分。

可用库存＝实物账面库存－已预留－不可用库存。预留与不可用不得重叠重复扣减；批次被隔离时同步重新评估订单分配。

INV-03：调拨请求不增加597库存；实际发出减少来源仓并进入在途，实际签收减少在途并增加目的仓。部分签收保留剩余在途，短缺与损坏进入差异处理。

INV-04：单位换算须由商品主档定义；同一SKU不同包装规格不能默认相等。

INV-05：首版支持每SKU、每仓配置安全库存，例如30箱，并显示预留后可用量。

INV-06（P2-C）：动态补货建议使用已确认订单、去重后的需求预测、调拨/国内采购提前期、在途到期量、安全库存、保质期和冷库容量。区分597向外库调拨和美国总体向国内补货，不能等外库耗尽才触发。

INV-07：补货建议显示计算依据、数据时间和置信度；用户可调整数量并记录理由。缺货造成的低出货量不能直接视为低需求，一次性大单单独标注。

INV-08：库存支持库位（库区/货架/托盘位）维度；库位可打印标签并扫码。

### 6.2 扫码与标签

SCN-01：手机和平板浏览器直接调用摄像头扫码，首版至少支持QR码和Code 128；GS1-128、DataMatrix作为可配置扩展。设备不支持或条码损坏时可手动输入，记录标注“手输”。

SCN-02：可扫码对象包括SKU、Lot、库位、托盘、生产批次和设备资产。扫码结果直接打开对应记录，或填入当前操作（收货、拣货、调拨发出/签收、领料、退料、盘点、检查）。

SCN-03：扫码时即时校验：Lot不属于当前单据、批次被隔离或过期、库位与单据不符、SKU与包装规格不符时提示并阻止过账；质量隔离不可越过，其他差异按权限进入差异处理。

SCN-04：盘点和收货支持连续扫码模式，自动累计数量；重复扫描同一托盘或同一标签时提示，不重复计数。

SCN-05：供应商自带条码可登记映射到内部SKU或Lot；未映射条码提示建立映射，不自动新建SKU。

LBL-01：标签模板包括原料Lot标签、托盘标签、成品批次标签和库位标签。字段从业务记录取值（SKU、品名、Lot、生产/到期日期、重量或箱数、条码/二维码、场地）；模板有版本，经食品安全/质量负责人批准后生效。

LBL-02：首版按指定标签尺寸（如4×6英寸）生成PDF，通过系统打印对话框打印到标签打印机；直连热敏打印机（ZPL等）列为P1扩展，打印机型号见附录A。

LBL-03：每次打印记录模板版本、操作人、时间、份数和关联记录；重打标注“重打”；作废的标签编码不能再用于扫码过账。

LBL-04：法规标签内容（成分、过敏原、净含量、营养信息等）由食品安全/合规负责人确认。系统只按批准模板渲染，不自动生成法规文本。

### 6.3 生产与清洁

PRD-01：生产准备检查至少覆盖原料（含Lot与质量状态）、设备、人员及操作授权、当前SOP、开工卫生和适用的检查协调事项。

PRD-02：准备条件分为“硬性”和“提示”两类，由质量负责人与运营主管共同配置。**默认方案（待业务确认，见附录C）：** 硬性条件未满足时批次不能开工；运营主管可填写原因并签名越过，形成异常标签并通知老板；质量隔离、未放行或过期原料属于不可越过条件，任何角色都不能越过。提示类条件只显示提醒。

PRD-03：工序模板包括收货储存、切菜、切肉、配料腌制、包装贴标、成品入库、停产清洁与再开工。每工序关联操作SOP和相应清洁检查表，记录执行人、时间、结果、实测值、证据及异常。

PRD-04：领料和退料通过扫码记录原料Lot与数量，作为追溯链路的投入端；未扫码或手输的领料在追溯结果中标注。

PRD-05：配方、采购余量、操作参数分别版本化。采购15%余量不改变配方比例。生产批次固定引用批准的配方/SOP版本；新版本发布不回写历史批次。

PRD-06：质量状态独立于生产进度：生产完工不代表可发货。具体清洁浓度、接触时间、温度等参数由现场食品安全负责人依据实际条件制定并批准。

### 6.4 质量与追溯

QLT-01：不合格处理闭环：不合格→控制影响（隔离受影响批次与库存）→整改→复查→关闭。只有照片、没有结果和核验不能关闭。

QLT-02：被隔离批次禁止分配、领用或发货，服务端强制执行；隔离时自动列出受影响的订单、预留和在途。

QLT-03：批次放行必须有放行理由、依据和放行人电子签名（REC-01）。

QLT-04：客户投诉关联成品批次和订单，可直接发起追溯。

TRC-01 正向追溯：从原料Lot查到使用它的生产批次、产出的成品Lot、当前库存位置及已发货的订单、客户和数量。

TRC-02 反向追溯：从客户、订单或成品Lot查到成品批次、所用原料Lot、供应商及收货记录。

TRC-03：追溯结果展示数量平衡（投入、产出、损耗、剩余库存、已发货）。链路缺失（如缺领料记录、手输未核验）时明确显示“追溯不完整”及缺口位置，不能静默跳过。

TRC-04：追溯结果可导出可排序的电子表格（CSV/XLSX）和PDF摘要，包含关键追踪事件（收货、转化、发货）的时间、地点、数量、批次和对方。FSMA 204食品追溯规则（要求在FDA请求后24小时内提供可排序电子记录）是否适用于597产品，以及所需字段，由合规负责人确认（附录C）。

TRC-05（P1）：可从任一Lot发起模拟召回演练，记录开始与结束时间、找到的数量与去向、缺口，作为质量记录保存。

目标：系统内5分钟内完成一次正反向追溯并导出（T-TRC-01）。

### 6.5 任务、采购和订单

TSK-01：通用任务状态为待开始、进行中、受阻、待核验、已完成、取消；显示规则见4.5节。负责人、截止时间、下一步、依赖及完成条件统一管理，业务单据可有自己的专用状态。

TSK-02：一项任务可被多个页面引用，只有一份记录。受阻必须填写阻碍原因和需要谁处理。

PUR-01：采购报价与需求版本关联；比较报价时含税、运费、安装费和交期。

PUR-02：采购余量（如5%、15%）作为需求版本的属性保存，不改写配方。

PUR-03：收货按行核对实收数量、Lot和签收依据；设备的发货、收货、安装、验收状态分别记录。

PUR-04 收货两步：现场提交收货单（不改库存）→ 上传签收单后由有入账权限的人签名入账（写库存流水，幂等）。库存物料行必须填写 Lot；可选“未核数”进入待核验库存；超过未到数量需填写超收原因；拒收需填写原因并自动生成差异任务；剩余数量可由采购“按短收关闭”。

PUR-05 审批：采购单金额（含税运安装费）超过审批额度（默认 2,000 美元，由老板设置）时提交后进入待审批，由老板电子签名批准或驳回（驳回须写原因）；提交后不能再改供应商、金额与行。

PUR-06 发票与付款：系统显示订单金额、应付参考额（按已收货计）与发票金额，差额超过 1 美元标红；上传付款证明只进入“已付款待核对”，由财务在有发票原件的前提下签名核对，金额不符时须填写差异说明。

ORD-01：订单部分送达按行核销，关联补货PO不重复计算需求。

ORD-02：拣货通过扫码确认SKU与Lot，隔离或过期批次被拦截；发货记录Lot作为追溯链路的输出端。

ORD-03：签收差异（短缺、拒收、损坏、退货）进入差异处理并影响应收核对。付款证明上传不自动意味着财务核销完成。

### 6.6 提醒、通知和审批

NTF-01：支持到期、缺记录、状态变化和阈值触发；每条规则定义对象、触发条件、接收角色、频率、升级时限和关闭条件。重复事件合并提醒；异常解决后关闭，超时才升级。

NTF-02：首版提供站内通知和PWA网页推送。iOS需将系统添加到主屏幕（iOS 16.4及以上）才能收到推送，系统在首次登录时引导。推送内容只含事项标题和链接，不含金额明细、人事信息或密码。

NTF-03：邮件通知P1启用；微信、短信通知列为P2，渠道和服务商待选型。对外发送与内部提醒分别授权。

APR-01：金额、库存调整、质量放行和重要验收可配置审批角色和额度；审批需电子签名。

APR-02：操作者能否自审由规则明确，关键放行和敏感更正默认分人复核（同SEC-06）。

### 6.7 电子记录与签名

REC-01 电子签名：核验、放行、审批和关闭异常时，记录签署人、时间（UTC存储，显示场地时区）和签署含义（如“已核验”“批准放行”“同意例外”）。签署时需重新输入密码或PIN。签名绑定记录版本；记录之后被修改时，签名显示为针对旧版本，需重新核验。

REC-02 审计日志只追加：任何角色（含系统管理员）都不能通过界面或常规接口修改或删除审计日志；日志按批次做哈希链或定期写入独立备份，以便发现篡改。

REC-03 保留期限：按记录类型配置（质量、生产、追溯、清洁、培训记录默认保留不少于2年，具体期限待合规确认）；保留期内不能删除，到期后进入待审批销毁清单，不自动删除。

REC-04 快速导出：按日期范围、Lot、批次、记录类型导出记录、签名、修改历史和证据清单（CSV/PDF），用于检查或审计。

REC-05：597产品中如含肉类加工，是否适用USDA FSIS的HACCP记录要求（含电子记录与签名要求），由合规负责人确认（附录C）；结论可能改变REC-01至REC-04的默认参数。

### 6.8 公司 Notebook：共享账号、联系人与笔记

NB-01：独立Notebook页面包含“共享账号”“重要联系人”“公司笔记”三个标签页。支持自建分类、置顶、收藏、标签、授权范围内搜索及关联业务记录；其他页面可添加Notebook组件，权限保持一致。

**共享账号。** 公司内部大量账号由多名员工共用，Notebook以“方便授权人员查到并使用”为目标，同时避免密码以明文散落在聊天、笔记和表格中。

每个账号记录服务名称、分类、登录网址、用户名/登录邮箱、客户或账户编号、用途、公司/场地归属、负责人、关联联系人、状态、最后核验时间、续费日期和备注。分类可包括邮箱、供应商采购、租车、政府注册、水电网、财务软件和设备管理。

NB-02 存储：密码保存在专用的应用层加密字段中，数据库中只存密文；加密密钥通过服务器环境配置，不写入代码仓库。密码不能保存在备注、笔记、评论、通用文本字段或附件中；系统识别疑似密码的文本时提示改用密码字段。

NB-03 可见范围：账号元数据（服务名称、网址、用户名、用途）与密码分开授权。每个条目可设置“可查看密码”的角色和/或指定人员；默认可见人为条目创建人、运营主管和老板。共享范围由老板、运营主管或条目创建人管理。页面管理员、系统管理员不因页面或系统权限自动获得密码。

NB-04 查看与复制：密码默认掩码，授权用户点击即可显示或复制；“显示前重新验证身份”“显示后自动隐藏”为可选配置，默认关闭。复制时提示剪贴板由用户设备管理。

NB-05 审计：记录谁在何时查看、复制、修改密码或调整共享范围；审计日志和历史记录只显示“密码已更新”，不记录新旧值。

NB-06 排除范围：密码和恢复码不进入全局搜索、OCR/AI处理、通知、报表、CSV/Excel导出、页面复制和普通历史差异视图；不出现在URL、服务器日志或分析事件中。

NB-07 两步验证信息：记录账号是否启用两步验证、验证方式、接收验证码的手机号或邮箱、谁持有该设备。恢复码如需保存，放在同样加密的独立字段中，适用NB-02至NB-06。

NB-08 离职与调岗：人员离职或调岗时，系统列出其曾有权查看的共享密码条目，生成“在外部服务改密并更新Notebook”的任务，按条目负责人分派；必须由负责人在外部服务改密后确认关闭，只修改Notebook中的文字不能关闭任务。同时立即撤销其Notebook权限。

NB-09：后续如需要更高等级的密码管理，可对接现有密码管理工具，Notebook只保留元数据与链接；首版不依赖此能力。

**重要联系人。** 联系人记录姓名、公司、职位/职责、分类、手机号、座机及分机、邮箱、微信或其他联系方式、语言、时区/工作时间、紧急联系人标记、替代联系人、内部对接人、最后核验日期和备注。字段按需要填写，不强制收集全部信息。

NB-10：支持手机一键拨号、复制联系方式、打开邮件撰写入口；打开入口不自动发信。可关联供应商、客户、外库、设备、合同、账号、订单与任务。联系人主档统一引用，避免采购页与Notebook各维护一份；合并重复联系人需预览，保留原记录关联。可上传名片照片、PDF和沟通附件，建立沟通时间线及跟进任务。

NB-11：初始分类建议为TT客服、外库物流、肉/香料供应商、租车、维修电工、垃圾/pest control、水电网、检查协调、人事财务。已有Wayne、Ware、Velocity等联系人可在核验后导入；本PRD不代表已导入或已获取任何密码。

**公司笔记。** NB-12：支持富文本、清单、链接、图片和PDF；按主题分组，可关联任意授权业务记录，支持历史版本与归档。可把待办段落转为任务。普通笔记中不保存密码，提示改用共享账号的密码字段。

## 7. 关键用户流程

### 场景A：随时增加“冷库巡检”页面

运营管理员从“周期检查”模板新建页面 → 选择597场地 → 添加温度检查表、异常列表、图片区和趋势图 → 关联冷库设备 → 设置负责人、频率、必填字段、阈值规则和权限 → 预览后发布。员工提交超阈值温度时生成整改任务，老板首页显示未解决异常。只发布页面不会生成虚假的历史检查记录。

### 场景B：已有采购页增加“安装验收”模块

管理员添加验收表格组件并绑定设备采购记录 → 配置安装日期、安装人、测试结果和验收照片 → 发布。原采购记录不复制；同一研磨机的发货、收货、安装、验收状态分别显示。隐藏模块不会删除验收证据。

### 场景C：外库调拨到597

仓管选择SKU、Lot、数量及单位 → 发起调拨 → 上传外库确认/BOL → 记录实际发运 → 现场扫码托盘标签、拍照并填写实收 → 差异进入核验 → 正确数量入账。一个BOL可关联多条SKU行，重复点击提交不得重复过账。

### 场景D：清洁不合格

员工按工序检查表提交结果和证据 → 不合格项创建异常并关联设备/批次 → 负责人整改并补充照片和记录 → 核验人复查并签名 → 满足条件后关闭。替换照片保留版本；只有照片、没有结果和核验不能自动关闭。

### 场景E：上传截图更新进度

用户在首页上传交期截图 → 系统识别并提供调拨单候选 → 用户核对原图和字段差异 → 确认预计日期与跟进任务 → 系统更新记录、关联证据并刷新相应页面。若并发修改或日期含糊，进入待确认冲突而不覆盖。

### 场景F：同一发票来自三个来源

先上传发票照片并建立采购费用草稿 → Gmail（或转发到接收地址）接入相同发票 → 系统追加来源 → QuickBooks同步对应财务记录 → 按发票身份匹配并关联财务镜像。余额与付款按财务来源核对，全过程不新增重复报销或库存入库。

### 场景G：证据跨页复用

采购上传发票 → 财务在报销记录中选择同一文件版本 → 分别填写用途和核验结果。普通现场员工即使看到相关设备任务，也不能读取财务敏感附件。取消报销引用不删除采购发票。

### 场景H：共享平板扫码收货

现场员工在冷库门口的共享平板上点自己的头像 → 输入PIN，界面切换为其语言（如西班牙语） → 打开“收货”→ 扫采购单二维码 → 连续扫描托盘标签，系统累计箱数并提示一托重复扫描 → 拍签收单 → 提交为待核验 → 仓管主管核对后签名入账。员工离开2分钟后平板自动锁回人员选择屏。

### 场景I：客户投诉追溯

质量负责人从投诉记录点击“追溯” → 系统反向列出成品批次、所用原料Lot及供应商 → 再从可疑原料Lot正向列出所有受影响成品批次、库存和已发货客户 → 一键隔离剩余库存 → 导出可排序报表。链路中有手输未核验的领料记录时，报表标注“追溯不完整”。

## 9. 资料接入与更新中心

### 9.1 目标、入口与分阶段

建立统一的“接收资料—识别—匹配—提出变更—确认—更新—留证”流程。资料不仅作为附件归档，还能生成结构化字段、业务进度和跟进任务；每一步都保留原始依据。

| 阶段 | 资料中心交付内容 |
|---|---|
| P0-A | 数据结构（SourceItem、Extraction、ChangeSet等）；上传入口；“仅存证”；待整理、已驳回、失败等视图 |
| P0-B | 手动上传、对照原件提出变更、记录匹配、变更确认界面、冲突处理、应用与撤销；Agent 接口提出的变更走同一流程（§9.11） |
| P1 | Excel/CSV导入复用资料中心；处理看板统计 |
| P2-A | Gmail接入（见9.7）；服务端自动 OCR/AI 识别随邮件接入一起建设 |
| P2-B | QuickBooks接入（见9.8） |
| P2-C | 经验证的低风险规则自动更新 |

ING-01：首页提供“上传资料”，支持手机拍照、相册、截图粘贴和PDF批量上传；订单、采购、库存、设备、联系人等详情也提供就地上传。就地上传携带当前记录上下文，但系统仍需检查资料是否属于该记录。用户可选择“识别并建议更新”或“仅存证”。

ING-02：资料中心包含待整理、处理中、待确认、冲突、已应用、仅存证、已驳回、失败等视图，显示负责人、等待时长、来源、关联记录和下次动作。不能确定归属时进入待整理，不默认创建正式订单或财务记录。

### 9.2 来源与适用更新

| 来源 | 提取与匹配对象 | 建议动作 | 保存的来源证据 |
|---|---|---|---|
| 采购收据/发票照片 | 商家、日期、发票号、商品、金额、币种、税运费 | 关联采购/报销，补充费用或生成草稿 | 原图、识别区域及确认记录 |
| 微信等聊天截图 | 联系人、事项、时间、交期、数量及单位 | 更新预计交期、增加待办、补充沟通记录 | 原截图与上下文完整性标记 |
| BOL/签收单/PDF | PO、SKU、Lot、箱数、实收量、差异 | 提议发运、收货或差异处理，待仓管确认 | 原文件及页码、签收依据 |
| 安装/清洁现场照片 | 设备、位置、阶段、可见问题 | 关联任务并提议待核验状态 | 原照片、提交人、发生时间 |
| 名片/联系人截图 | 姓名、公司、电话、邮箱、职责 | 新建或更新联系人草稿，提示重复 | 原照片与核验记录 |
| Gmail / 转发邮件 | 报价、预约、交期、补件、附件、回复 | 归档到记录、提出更新、建立跟进任务 | 邮件身份、时间、正文及获准保存的附件 |
| QuickBooks | 客户、供应商、账单、发票、付款分配、应收应付 | 按字段映射同步财务镜像，提示业务差异 | 外部记录ID、版本、同步快照/链接及可取得附件 |

现场照片不能单独证明清洁参数合格、安装验收完成或库存箱数准确。聊天截图中的“已发货”不能推导为“已签收”；截断内容、模糊数字及缺失单位必须标注待确认。

### 9.3 识别与业务匹配

ING-03：提取结果保留字段值、单位、币种、日期时区、来源页码/区域、识别置信度及缺失原因。优先按外部ID、PO号、发票号、SKU/Lot、条码等明确标识匹配；联系人、金额及时间用于辅助。多条候选必须让用户选择，不能仅因金额相同就认定同一单据。

ING-04：识别模型或规则只生成受控结构化建议。邮件、PDF或图片中的文字均作为业务资料，不作为执行指令；其中要求泄露数据、调用工具或改权限的文字不能触发动作。识别仅使用当前用户和连接账号获准处理的业务数据。

ING-05：允许新页面声明可识别记录类型、可映射字段、匹配键和允许动作，并复用统一流程；未注册的自定义字段进入待人工映射。AI不能借助通用页面配置绕过库存事务、质量放行或Notebook密码权限。

### 9.4 变更确认界面

ING-06：采用“原资料预览＋逐项变更清单”。每项展示目标记录、原值、建议值、证据位置、建议原因、置信度、影响和所需权限。支持全部接受可独立且有权限的建议、逐项确认、编辑、改关联、驳回、仅存证和指派核验人。

示例：上传Wayne聊天截图，匹配某调拨单，建议预计到货从周二改为周三，同时创建“确认TT配送影响”任务并关联原图。页面明确说明没有修改实收数量。

ING-07：应用前重新校验目标记录版本、用户权限、金额/单位和业务状态；用户审阅期间数据被别人修改时转为冲突，不静默覆盖。单笔库存动作与证据关联原子提交；跨多笔记录的变更分组显示成功、失败及未处理项，不把部分成功标为全部完成。

ING-08：资料处理状态与业务完成状态独立。“建议已应用”只说明已写入获批字段，不能替代收货核验、付款核销或质量放行。系统保存处理人、确认人、时间、规则/识别版本、前后值及证据版本。

### 9.5 自动化分级

| 级别 | 允许动作 | 启用条件 |
|---|---|---|
| 自动接收与分析 | 收集授权资料、去重、提取、生成建议 | 用户已授权对应来源范围；不改变正式业务事实 |
| 低风险规则更新 | 给确定记录追加邮件证据、生成提醒、同步已配置财务镜像字段 | 管理员明确配置规则、范围及日志；可暂停 |
| 人工确认更新 | 实收数量、库存调整、金额冲突、重要状态、联系人合并 | 有相应业务权限的人员逐项或按业务组确认 |
| 专门审批操作 | 质量放行、付款执行、对外发信、写回外部财务系统 | 使用各自独立授权流程，不由识别置信度替代 |

首版所有识别产生的正式业务字段修改均需确认。后续规则自动化先以“仅建议”试运行，检验误匹配和重复处理后再单独启用。用户可一键暂停某来源或规则，不删除已留存历史。

### 9.6 去重、权威来源与冲突

ING-09：区分文件去重、来源事件去重及业务去重。相同文件按校验值识别；Gmail按连接账号和message ID识别（转发邮件按原始Message-ID头识别），thread ID仅用于关联，不能吞掉后续新回复；外部财务记录按公司、对象类型、ID及版本识别。不同照片或转发件可归于同一发票，但原始来源各自保留。

ING-10：一张发票同时来自照片、Gmail和QuickBooks时，应汇总到一个业务对象并追加来源，不重复报销、记账或收货。疑似重复进入核验；贷项、作废、退款、部分付款及更正版不得简单当作相同发票忽略。

| 数据类型 | 权威来源与更新规则 |
|---|---|
| 财务账单、发票、付款分配及余额 | 完成映射后以指定QuickBooks公司内记录为财务镜像依据；不自动改内部采购验收事实 |
| 实物库存和收发货 | 以本系统经授权过账流水为准；邮件、截图与外部报表是待核验依据 |
| 预计交期、预约和沟通 | 由已确认的最新业务沟通更新，保存生效时间与旧值 |
| 客户、供应商、联系人 | 为每个字段指定主维护系统，冲突由负责人确认；不使用笼统“最后写入获胜” |
| 质量放行、清洁验收 | 以授权核验记录为准，外部资料不能直接覆盖 |

ING-11：保留事件发生时间、来源更新时间、接收时间和应用时间。旧邮件延迟导入不得倒退新状态。金额、数量、批次或来源间矛盾进入冲突队列，指定负责人；无法判断时保留现有已核验值，并展示待处理差异。

### 9.8 QuickBooks接入（P2-B）

ING-18：开发前先确认使用QuickBooks Online还是Desktop。Online通过官方API对接；Desktop需通过Web Connector或SDK在装有QuickBooks的电脑上运行，工作量、部署方式和稳定性差别很大，两者需分别评估（附录C）。使用Online API时，生产环境密钥需通过Intuit开发者平台的应用审核。

ING-19：先实现单向读取与核对，再单独评审写回。首次连接明确公司身份、日期范围、币种、客户供应商映射和字段归属。账单/发票/付款是不同对象，支持部分付款、贷项、退款及作废对余额的影响；订单已送不自动视为已付款。仅同步接口实际可取得的附件；拿不到附件时显示“无附件/待补”，不伪造证据。

ING-20：财务镜像保留外部ID、版本和最后同步时间，本系统订单与库存独立关联。后续如支持写回，必须具备单独权限、变更预览、幂等、回执及失败对账，首版不包含外部付款执行。

### 9.9 失败处理、纠正与证据链

ING-12：同步、识别、匹配、确认、应用分别记录状态。模糊图片支持重传、手动补录或仅存证；服务超时、连接撤销、限流可重试并显示原因。重试从失败步骤恢复，不能重复执行已经成功的库存或财务动作。

ING-13：普通字段可在版本检查后撤销；已过账库存通过冲销与更正，已同步财务变更通过相应会计系统的受控更正流程处理。撤销业务更新不删除原始证据。文件被替换或源记录被作废时保留历史，重新评估受影响的建议与引用。

ING-14：原资料、提取版本、匹配候选、审核决定、实际应用结果、错误与重试均可追溯。Notebook密码与恢复码不进入OCR/AI流程、搜索或处理日志；其他敏感业务资料仅在授权范围处理。来源链接失效不等于证据已核验或应被删除。

### 9.10 现有导入与搜索

ING-21：Excel/CSV保留导入预览、字段映射、单位检查、重复项提示、逐行错误和确认步骤，复用资料中心。历史不确定库存进入待核验库存（INV-02），不能转为可靠期初库存。

ING-22：全局搜索仅覆盖授权记录、文件名称、标签及获准索引的OCR内容；按来源、页面、负责人、处理状态和日期筛选。接入看板统计等待时长、未解决冲突、重复拦截、失败及已应用数量，不把提取数量当作业务完成量。同步不可用时老板首页显示数据陈旧提示。

### 9.11 Agent 接口层：开放给手机上的 ChatGPT / Claude

**决策：** 系统不内置 AI 对话或自建模型调用，而是开放一层受控接口，让用户在自己手机上的 ChatGPT（老板主要使用 ChatGPT 个人版，位于美国和加拿大）或 Claude 里直接操作。外部 AI 是“又一个客户端”，以授权用户本人的身份调用，系统已有的权限、证据规则、幂等和版本冲突检查原样生效，不为 AI 另开通道。

**收益：** 不自建对话界面、不承担模型费用、不维护提示词，模型升级自动受益；老板在手机上一句话即可看全局。**代价与限制：** 外部 AI 只能由人主动发起，不能承担后台定时同步（Gmail、QuickBooks、每日检查仍在服务端）；对话中拍的照片目前不能原样传给工具，AI 对图片的描述只能作“转述”，不能当证据。

| 编号 | 要求 |
|---|---|
| AGT-01 协议 | 提供远程 MCP 服务（Streamable HTTP，`/mcp`），供 ChatGPT 连接器（开发者模式）和 Claude 使用；同一套工具另以 OpenAPI 形式提供（`/agent/openapi.json`），作为“自定义 GPT + Actions”备用路线——手机端可用性以实测为准，两条路线共用实现。 |
| AGT-02 授权 | OAuth 2.1：动态客户端注册、PKCE（S256）、授权码与刷新令牌（轮换）；自定义 GPT 使用管理员签发的机密客户端，回调限 `chatgpt.com/aip/` 前缀。用户用本人系统账号登录并勾选“读取 / 写入”范围；不使用共享 API 密钥。用户须先在「我的设置 → AI 助手」开启；系统管理员角色不能连接。 |
| AGT-03 分级 | **读取**：总览指标（含口径与深链接）、搜索、任务/记录/库存/调拨/追溯、待核验证据元数据、资料中心队列、联系人、人员。**低风险写入**：评论、新建任务/上报异常、更新本人任务进度（不能标记完成，须带版本号）。**提出变更**：生成待确认变更进入资料中心，由人逐项确认后生效，同时保存“AI 转述（非原件）”存证。**永不开放**：质量放行、证据核验、库存过账、付款、密码与恢复信息、人事附件、用户与权限、页面发布——AI 只返回深链接，由人在系统内完成。 |
| AGT-04 原件 | 需要原件时，AI 调用“生成上传链接”：30 分钟有效、只能上传到指定的一项、最多 20 个文件、无需登录即可在手机上传；上传结果为“未核验”证据。 |
| AGT-05 安全 | 令牌不透明、只存哈希、1 小时有效；每个连接可单独撤销，用户关闭开关即撤销全部连接，权限变更与停用对下一次调用立即生效；每连接每分钟限流；业务数据中的文字一律作为数据返回，工具说明明确要求 AI 不执行其中的指令。 |
| AGT-06 审计 | 每次调用记录：用户、客户端（ChatGPT/Claude）、工具、参数摘要、成功/失败；AI 引起的修改在修改历史中标注 `agent:<客户端>`；资料中心对 AI 提交的条目单独标识。 |
| AGT-07 手机体验 | 所有返回结果附带系统深链接；深链接、授权页、上传页、确认页均满足 §10.5 手机要求。 |
| AGT-08 数据 | 发往 OpenAI 的业务数据已获批准（含财务）；仍不发送密码、恢复信息和人事附件。ChatGPT 个人版用户应在「设置 → 数据控制」关闭“为所有人改进模型”。 |
| AGT-09 演进 | 先“读取 + 提出变更”；运行一段时间、统计误匹配率和被驳回比例后，再逐项评审是否开放更多低风险直接写入。任何直接写入都不能替代核验、放行、过账的专用流程。 |

## 10. 体验与非功能要求

### 10.1 多语言

I18N-01：现场流程（当班任务、检查表、拍照上传、扫码收货/拣货/盘点/领料、打卡、异常上报、Notebook联系人查看）完整支持中文、英文、西班牙语界面，不只是字段标签。语言跟随用户设置；共享设备切换人员时随之切换。

I18N-02：业务主数据和配置内容（SKU名称、检查项、规则提示、模块标题）支持多语言字段；未翻译时显示原文并标注“未翻译”。

I18N-03：管理端（页面编辑器、财务、系统设置）首版提供中文和英文。

I18N-04：正式SOP翻译需业务批准，机器翻译只能作为参考草稿，不能成为有效版本。

### 10.2 现场设备与离线

FLD-01 操作条件：现场主要操作按钮高度不小于56px、间距足够，适合戴手套操作；主操作放在屏幕下半部；高对比度，强光下可读；数量录入使用大号数字键盘。

FLD-02 共享设备模式：系统管理员登记共享设备后，设备显示本场地人员头像/姓名列表，员工点选后输入个人PIN切换；闲置2分钟自动锁回；设备不保存个人登录密码；每条记录归属实际操作人；共享设备上不可查看Notebook密码、人事和财务敏感内容。

FLD-03 离线采集（P1）：照片、检查表结果和盘点计数可在无网络时暂存，明确显示“未同步”；恢复网络后上传，服务端按当前状态校验，冲突进入待处理。离线期间不得显示已审批、已过账或已签收成功。

FLD-04：完整离线同步和冲突合并放P2-C。首版（P0）允许在线状态下本地保存表单草稿和待上传照片，显示“未同步”。

FLD-05：页面统一提供搜索、筛选、负责人、更新时间和新增入口；有明确空状态、加载状态、权限不足和错误恢复。高风险操作前显示对象及影响，不在日常小操作中重复确认。桌面适合多表比较，手机适合当班任务、扫码、拍照和快速录入；所有核心现场流程在手机上可完成。

### 10.3 时区与远程访问

TZ-01：服务端统一以UTC存储时间；每个用户设置自己的时区。关键时间（截止、交货、检查、签名）同时显示用户时区和场地时区，例如“周三 10:00 洛杉矶 / 周四 01:00 北京”。

TZ-02：截止日、“当天应填记录”、日报统计按场地时区计算。

TZ-03：托管区域和从中国访问的速度与可用性列为待决策（附录C）；系统前端不依赖在中国无法访问的第三方资源（字体、地图、脚本CDN等）完成核心功能。

### 10.4 性能、备份与安全基线

NFR-01：建议性能验收基线：50个并发用户、10万条业务记录及5万份附件元数据下，分页列表和常用查询P95不超过2秒，核心页面首屏P95不超过3秒（约定测试网络与设备，文件传输时间另计）；扫码到结果显示P95不超过1秒（不含网络中断）。大表使用分页，图表异步加载，上传不阻塞其他工作。

NFR-02：上线前配置加密传输、受控文件存储、审计、自动备份与恢复演练。建议恢复点目标24小时内、恢复时间目标8小时内；若生产连续性要求更高，应在上线前调整预算和目标。

NFR-03：权限撤销后新请求立即生效，已签发文件访问链接需短时有效。

### 10.5 手机端适配与手机验收

老板很可能只用手机做验收，现场人员也以手机为主。手机端不是桌面端的缩小版：所有关键节点必须在手机上**看得清、点得准、做得完**。任何一项手机验收用例未通过，对应阶段不能退出。

**基准设备：** 以 390×844 竖屏（iPhone 14 等同尺寸）为验收基准，同时在 360px 宽的 Android 机型上抽查；iOS Safari 与 Android Chrome 均需通过。桌面端布局在 ≥1024px 时保持多列比较能力，不因手机适配而退化。

| 编号 | 要求 |
|---|---|
| MOB-01 布局 | 任何页面不得出现整页横向滚动或内容被截断。数据表格在手机上改为卡片列表（关键字段优先，例如库存卡片首先显示“可用量”）；看板改为“状态切换＋单列列表”，不要求左右滑动寻找列。只有明确的横向切换条（状态、页签）允许横向滑动。 |
| MOB-02 触控 | 可点击元素的触控区域不小于 44×44pt（次要图标按钮不小于 36×36）；相邻按钮间距足以避免误触；现场主操作按 FLD-01 不小于 56px。拖拽排序必须同时提供按钮排序（上移/下移），并有触屏拖动手柄。 |
| MOB-03 输入 | 输入框字号不小于 16px，避免 iOS 聚焦时页面自动放大；不禁止用户双指缩放。数量字段调起数字键盘，日期使用系统原生选择器，搜索框使用“搜索”键。 |

| MOB-07 证据查看 | 图片可双指缩放、旋转；PDF 在手机上用系统查看器打开（可翻页、缩放），不得只显示第一页；拍照直接调起后置摄像头；上传逐文件显示进度与失败重试。 |

| 总览与下钻 | 看全部指标→点进明细→看到负责人、处理过程和证据 |
| 任务/异常 | 查看待决策、受阻、待核验；查看证据；核验通过或驳回；例外放行（填写原因） |
| 证据 | 预览图片与 PDF 原件，看到版本、上传人、核验状态 |
| 采购/设备验收 | 查看记录与证据规则，变更状态，上传验收照片 |
| 库存与调拨 | 看可用量、在途、未核数、隔离；收货、发运、部分签收、盘点 |
| 质量 | 隔离与放行（电子签名）、追溯查询与导出 |
| 检查表 | 现场提交（含拍照、超范围、不适用理由），不合格自动生成整改 |
| 资料中心 | 上传截图/照片，对照原件确认或驳回变更，冲突处理 |
| Notebook | 查找联系人一键拨号/发邮件；授权人员查看共享账号 |
| 页面编辑 | 新建页面、添加与配置模块、预览、发布与回滚 |

## 11. 交付阶段与优先级

| 阶段 | 必交付内容 | 退出标准 |
|---|---|---|

| P2-B 财务对接 | 确认QuickBooks版本后单向读取、字段映射、账单/付款核对、财务镜像及同步异常 | 同一发票跨来源不重复，部分付款与作废可对账 |
| P2-C 自动化与计划 | 经验证的低风险规则更新、按 AGT-09 评审后扩大 AI 直接写入范围、动态补货、打卡对接、完整离线同步、微信/短信通知 | 自动更新可暂停、预测可解释且不绕过人工权限 |

所有业务页面可从第一阶段用通用模块建基础台账，但未开发的专用能力必须标识清楚；不能用可编辑表格冒充库存事务、工资系统、追溯或质量放行逻辑。

## 13. 上线前确认事项
